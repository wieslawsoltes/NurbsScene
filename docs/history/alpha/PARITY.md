## Acceptance rules for further work

Unsupported behavior must be rejected before creating substitute geometry. Modeling accuracy needs independent fixtures and quantified tolerances, not just attractive screenshots. GPU success needs real API initialization, validated shaders, nontrivial framebuffer output and interaction/device-loss tests, not a method named `render` returning metrics. Uno success requires running the compiled Uno host, not the JavaScript harness. Product parity requires an enumerated reference inventory and behavioral/visual comparison across supported hosts.

The first implementation step for full solid modeling is the missing exact B-rep/topology backend—not additional buttons over surface meshes. The first release qualification step is a successful managed/Uno build and the GPU-required browser gate. These are unfinished requirements, not deferred background tasks.
